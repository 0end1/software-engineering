# Software Engineering（软件工程）

## Overview

以工程化方法开发高质量、低成本、易维护的软件系统。本技能将完整的软件工程流程拆解为可执行的工作流，并根据项目需求特点**自主选择最合适的开发模式**，同时支持在开发过程中**自由切换模式**以适应需求变化。

核心价值：
- **规范化开发**：遵循统一流程和标准
- **团队协作**：多人分工合作
- **全过程管理**：覆盖需求→设计→开发→测试→部署→维护
- **质量保证**：评审、测试和持续改进

## 开发模式选择决策树

**在开始任何开发任务前，必须先评估项目特点并选择开发模式。** 评估以下维度：

| 评估维度 | 询问/判断依据 |
|---------|--------------|
| 需求明确度 | 需求是否清晰、稳定，还是模糊、频繁变化？ |
| 项目规模 | 大型高风险项目还是中小型项目？ |
| 交付节奏 | 需要一次性交付还是增量/快速交付？ |
| 用户反馈 | 用户能否频繁参与并提供反馈？ |
| 风险程度 | 项目技术或业务风险高不高？ |

**选择逻辑（按优先级判断）：**

```
需求是否明确且很少变化？
├── 是 → 瀑布模型（Waterfall）——文档齐全、管理简单
├── 否 → 需求可否通过快速原型澄清？
│   ├── 是 → 原型模型（Prototype）——先做原型再定需求
│   └── 否 → 项目是否大型且高风险？
│       ├── 是 → 螺旋模型（Spiral）——风险驱动迭代
│       └── 否 → 是否需要快速交付 + 持续反馈？
│           ├── 是 → 敏捷开发（Agile）——小步快跑持续交付
│           └── 是（需分批交付）→ 增量模型（Incremental）——分次增加功能
```

**默认策略**：当信息不足时，优先采用**敏捷开发（Agile/Scrum）**作为默认模式，因为其适应性强；若用户明确要求严格的文档驱动或项目为合规型/固定需求型（如政府项目、医疗系统），则采用**瀑布模型**。

### 各模式特点速查

| 模式 | 适用场景 | 优点 | 缺点 |
|------|---------|------|------|
| 瀑布 | 需求明确、变化少 | 管理简单、易于控制 | 难应对变化、后期改造成本高 |
| 原型 | 需求不明确 | 快速澄清需求 | 原型可能被误当成品 |
| 增量 | 需分批交付 | 用户早使用、风险小 | 需要整体架构设计 |
| 螺旋 | 大型高风险 | 风险驱动、迭代可控 | 过程复杂、成本高 |
| 敏捷 | 需求变化快、需快速交付 | 快速迭代、持续反馈 | 文档少、需用户配合 |

## 工作流：一次完整的软件工程开发

选定模式后，按下列步骤执行。每一步的输出物都应符合软件工程规范。

### Step 1: 可行性研究

- 从**技术、经济、操作、法律**四个维度评估项目是否可行
- 输出：可行性研究报告

### Step 2: 需求分析

- 收集并梳理**功能需求**与**非功能需求**（性能、安全、可用性、可维护性）
- 输出：**软件需求规格说明书（SRS）**，参见 `references/document-templates.md`

### Step 3: 概要设计

- 设计系统**整体架构**：模块划分、接口定义、数据库设计、技术选型
- 遵循四大原则：**抽象、模块化、信息隐藏、高内聚低耦合**
- 输出：概要设计说明书

### Step 4: 详细设计

- 细化每个模块：类设计、数据结构、算法、接口详细规格
- 输出：详细设计说明书

### Step 5: 编码实现

- 遵循编码规范，编写可维护、可复用的代码
- 配合**单元测试**（TDD 时先写测试）

### Step 6: 软件测试

- 按层次执行：**单元测试 → 集成测试 → 系统测试 → 验收测试**
- 按是否了解内部结构：**黑盒 / 白盒 / 灰盒**
- 输出：测试计划、测试报告，参见 `references/testing-maintenance.md`

### Step 7: 软件部署

- 构建、发布、配置环境、部署上线

### Step 8: 运行与维护

- 按**纠错性、适应性、完善性、预防性**四类维护

**注意：维护阶段通常占整个软件生命周期成本的最大比例。**

## 开发模式的执行方式

不同模式会改变上述工作流的执行节奏。具体执行细则参见各参考文档。切换模式时，只需告知切换到哪一模式，技能会自动调整后续工作流节奏。

### 瀑布模型（Waterfall）

- **顺序执行**所有 Step，每阶段完成后严格评审再进入下一阶段
- 强调**完整文档**产出
- 详见 `references/development-models.md#瀑布模型-waterfall`

### 原型模型（Prototype）

- 先快速制作**可运行原型**，与用户反复确认需求
- 原型确认后再进入正式设计与开发
- 详见 `references/development-models.md#原型模型-prototype`

### 增量模型（Incremental）

- 将系统拆分为多个**增量**，按优先级分批交付可用功能
- 每批增量都包含完整的设计→编码→测试
- 详见 `references/development-models.md#增量模型-incremental`

### 螺旋模型（Spiral）

- **风险驱动**：每轮迭代包含计划、风险分析、开发、评审
- 适用于大型高风险项目，通过原型逐步降低风险
- 详见 `references/development-models.md#螺旋模型-spiral`

### 敏捷开发（Agile）

- **小步快跑**：短周期迭代（Sprint），持续交付可运行软件
- 常用方法：Scrum、Kanban、XP
- 强调**团队协作、用户反馈、持续改进**
- 详见 `references/development-models.md#敏捷开发-agile`
